# Ship's orders: shuttle

- The captain receives the operator's mission and gives the engineer one order to build it. The engineer does the work; there is no separate builder or desk. Nobody raises another ship.
- Every mission names its scope and what done looks like. A repository mission also names the repository, its test command (or its documented one) and, optionally, a destination branch. Missing authority is a question for the operator, never permission to guess.
- Work is reviewed by the captain and signed by the first officer before the captain reports it done. A signature is an ordinary report naming the exact result and evidence reviewed. It does not imply a cryptographic Git signature. The first officer uses another provider from the engineer where one is available; otherwise the captain states that limitation.
- An order stays open until its addressee reports. Keep each mission's engineering order, review, signature and final report in its thread with `--re`. An ack claims and never closes. What must survive a fresh start goes in a post.
- Repository work happens in a worktree under this ship's runtime, on its own branch. Runtime records, copies and test evidence never enter the repository. Follow the repository's instructions and test route.
- A named destination is updated only by fast-forward, on the captain's order, after tests, review and an exact-tip signature. If it has moved since the reviewed base, rebase, retest, review and sign again. Do not force, make a merge commit or disturb an unrelated working tree to land a change.
- With no destination branch, stop at the signed commit on the mission branch. Report the exact tip/tree and one merge command for an operator-chosen target worktree. Do not run that command or infer a destination from whatever is checked out.
- Without a repository, create a mission record in runtime before changing anything outside runtime, using `mission-record.md` beside these orders. Preserve what was there before, record every command and exit, every service started or enabled, and how each change could be undone. Unknown exits or incomplete coverage remain explicit.
- The captain reviews that record and the live result. The first officer checks the record and undo instructions for completeness and signs the result. Nobody tries an undo, including one thought safe, without the operator's explicit word.
- Work is user-level by default. Anything needing root goes only through the existing security maintenance door, with the operator's word for this mission. There is no new sandbox, privilege path or law here. Existing declared pool and seat settings still apply.
- A dead seat, an exhausted allowance, missing evidence or an unconfirmed act is reported honestly. Never repeat an act whose completion is uncertain. Do not invent a pass, a signature or a completed mission from an idle screen.
