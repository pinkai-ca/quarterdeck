# Quarterdeck design: Tests

A page of [the design](../DESIGN.md).

## 12. Tests

Four layers:

1. **Unit.** Pure logic: the ship file and its line editor, message records, inbox rendering, the typed form, attribution, the Ledger's arithmetic, the status line from a fixture state.
2. **Contract.** Each adapter against recorded screens and transcripts, one directory per proven version, with a check that every proven version has a fixture set; `qd check <harness>` is its live counterpart, and narrower: it proves that the installed program launches, takes a paste its record confirms, does one task and is read, and leaves every comparison with recorded files to this layer. Every interruption the adapter knows has a screen in the set, every control has the state that confirms it, the box's folding of a paste is recorded with its counter, and the claude set includes a subagent transcript.
3. **Integration.** The Drill on a real tmux server with `qd-fakeharness --as claude` or `--as codex`, a small program in the shape of one of those two: it shows a box that folds a long paste, a dialog, a program that queues while working and one that does not; it accepts a message, works for a while through steps, writes the record in the shape it takes, and replies. The other programs are proven by their contract fixtures and by `qd check`, not by the drill. Every seat sends to every other seat and the Watch confirms each delivery; the service is killed mid-delivery and recovers with no message lost or doubled; every seat is relaunched fresh and the matrix runs again; the Office seat receives messages through its watch, with only the guarded fixed waking line when a message waits and its watch is down.

   The crash check requires the public fresh delivery receipt, one delivered attempt, and one acceptance in the record. A dequeue and its later input echo may both describe consumption of the same enqueue; these count once by their original acceptance time, provided consumption is timed and valid. Separate direct acceptances and distinct enqueue times count separately. Queued, untimed or stale evidence cannot satisfy delivery. The simulator's independent submission count must also be one: input evidence alone cannot distinguish separate identical enqueues sharing a timestamp, and a live drill lacks that simulator counter.

   The fresh-start check proves that an open order appears in the new conversation's first input. A crew order need not reach the old conversation first: an unattempted order, or a finished withheld/cancelled/blind attempt, can be carried by the fresh start. A blind result is still unconfirmed delivery, not a receipt; it does not prevent this carriage check once its journal work is finished. Active attempts and typing/confirmation journals still settle before fresh, and the ordinary lifecycle claim serializes fresh with delivery. A Busy entry retries the whole readiness check; a started fresh is never retried. The human seat's watch must still accept its order. Output names whether delivery came first or the order was carried without prior acceptance; failed checks precede passes so truncated installed-command logs retain their names.

   The generated temporary drydock leaves `fresh = "after-order"` unset, so the drill owns its explicit crash and fresh transitions. An automatic fresh racing the next matrix can legitimately carry its new orders in the launch index, but the fake program executes only explicit `$ ` commands and does not follow indexed threads. Those orders would have launch receipts without executing their synthetic closing reports. The source drydock declaration and the service's after-order policy are unchanged; all 29 drill checks still run.

   Private suite fixtures and the standalone fake drill allocate a fresh mode-700 namespace outside tmux's shared socket directory and use its exact `-S` endpoint. `TMUX_TMPDIR` supplies an existing transport root when set; fallback is the framework project’s ignored `work/`, never an arbitrary caller directory. Paths, including a replacement suffix, must fit the native socket limit. The namespace creator creates its mode-600 lock/header; bound children and observers open only that existing validated regular lock, use `-N` to avoid bootstrapping a server, and gain no cleanup authority from `QD_TMUX_SOCKET`. Opening uses `O_NONBLOCK`/`O_NOFOLLOW` and checks the actual opened inode, so unfamiliar special files refuse without blocking or being repaired. Public generic observer commands accept only the known query/buffer/key transport queues; other commands, including mixed shutdown/unknown queues, refuse before dispatch. Required session, pane and status operations build fixed commands through the private validated dispatcher, preserving their target/session-token guards; whole-server shutdown remains creator-only. Named `-L` bindings retain their existing behavior; qd reaches tmux's default server only to find and finish a ship that has not moved to its own ([section 6](seats.md#6-seats)). Older framework revisions do not understand this new absolute private binding; a kept private drill needs the matching code or its printed native `tmux -S … -N` command, while existing ship declarations and record/ledger formats remain unchanged.

   A creator-started private server uses `exit-empty off`, so bound CLI/service observers can continue between sessions; its creator ends the server lifetime. A genuine last-session exit with that native option enabled still requires the same proved-dead endpoint removal before creator restart. Suite setup explicitly starts the creator before testing CLI observer launches. A session fixture also isolates intentional named/default no-server probes with a fresh short `TMUX_TMPDIR`. With the outer variable unset, the anchor is the fixed short `<project>/.testruns/s`, the project being the parent of the Git common directory, so the checkout, every linked worktree and every run checkout of `tests/testrun.py` share it; the folder is private, ignores itself and must be proven ignored by Git, and a link or a foreign or shared directory in its place refuses. It budgets the real nested isolation layout and native UID/PID/replacement names before allocation and keeps a margin of 12 bytes below the native limit on the deepest socket the suite generates; an irreducibly long project anchor refuses honestly rather than using shared or arbitrary temporary directories. It restores the caller’s environment and removes only its exact empty native UID directory and root with `rmdir`. Outer test containers retain their original directory descriptor through setup/teardown and compare identity before empty-only removal, including setup failure; replacement, nonempty or uncertain containers remain with a reason. Socket namespaces stay outside pytest and drill data trees that may be removed recursively.

   Creation, managed replacement and cleanup serialize through this namespace lock. Only known native query and buffer/key transport queues share the namespace stability lock, with a single nonblocking acquisition; server/session/window lifecycle commands, options and any generic or mixed queue outside that set take it exclusively and cannot bypass `-N` on a bound observer. Exclusive acquisition has one two-second budget (`EXCLUSIVE_WAIT`), then refuses with ownership uncertainty. A waiting exclusive operation goes before new shared leases: it marks the namespace folder itself with its own flock, never a new entry, and a reader that finds the mark answers busy as it does to an exclusive holder. Shared leases overlap one another and the wait is a nonblocking poll, so without the mark readers taking turns kept the lock shared through the whole budget though no read was slow, and a drill's fresh start on a loaded runner failed busy that way. A holder holds the lock for one tmux client command, which a loaded machine can take well over a quarter second to run, so the first budget of 250ms failed ordinary lifecycle and cleanup steps under a parallel suite; two seconds outlasts a slow command and still bounds a stuck one. Close takes at most two such acquisitions (four seconds aggregate), plus its existing bounded two-second shutdown check; lock expiry is not retried. Each tmux client command to a private server, creator's or observer's, is bounded by `PRIVATE_COMMAND_WAIT` (10 s, five times that lock budget, which a healthy server's command never nears on a machine running all four test slots): a stopped or hung server accepts the client's connection and never replies, so the command fails as unanswered (`TmuxUnanswered`, a private uncertainty, never evidence that the server or a pane is gone) and only the client, the caller's own child, is ended. Close then holds that server with the reason, its socket and ownership retained and no signal sent, and the same creator closes it once it answers again. Suspended holders therefore cannot indefinitely block status or confer cleanup permission. Private lock/ownership uncertainty propagates through pane/server reads instead of becoming a missing pane or server; status retains its independent service alarm, and lifecycle callers hold. Synthetic polling retries only that uncertainty within its existing deadline. The busy-actor fixture pauses between native namespace operations; separate held-lock cases exercise actual lease contention. Waiters revalidate the directory and actual held lock after acquisition. Creator evidence is separate for directory, server birth nonce/PID/start and the socket inode retained by descriptor. Cleanup stops only the proved server through an in-server identity condition, then requires ended-process and refused-connection evidence (a process whose `/proc` entry is gone, or reaped between opening and reading it, which the kernel answers with ESRCH, has ended, as has one `/proc` shows as Z, a zombie, or as X, x before Linux 4.14, for the instant of its reaping, the exited states the framework reads from `quarterdeck.procstat`; any other read error still refuses) plus the same socket identity before unlinking the exact endpoint under the held lock. Any observed replacement, live or uncertain endpoint is retained with a reason; a refusal alone is not ownership proof. Only the exact owned lock is removed when no peer or unfamiliar entry remains, followed by `rmdir`; socket roots are never recursively swept. This guarantee covers framework-managed operations following the lock protocol. A same-UID process mutating the namespace without taking that lock is outside it; ordinary POSIX unlink cannot atomically guard against such a swap.

   Ordinary successful completion removes private leftovers; failed or interrupted cleanup with known ownership takes the same path. Unprovable startup/cleanup or uncatchable process death can leave an explicitly held project-private namespace, never authorize adoption or a sweep. Drill data is retained if private shutdown is held, so recursive data cleanup cannot erase a live/foreign peer. `--keep` preserves the server, namespace and drill data, prints the quoted absolute endpoint/session command, and restores the caller’s previous transport environment. A kept namespace remains until its creator explicitly closes it; transport-only observers cannot reclaim it.

4. **Live drill.** Opt-in, real programs on throwaway seats, the same matrix plus one duty per role from its card and one task per seat that the drill can check without reading prose: write a named file with given contents, run a given command and report its output, post a report with given words. The drill verifies each by the filesystem and the post store, not by the reply, and emits a pass table. It spends real tokens and runs only when asked.

Two tests guard the repository itself: no runtime content, seat id or credential pattern in any tracked file, and every `runtime/` ignored; every law carried somewhere, every law tag real, and every law's test attempting its violation. File size is guidance, about 400 lines, split by concept and never compressed to fit a number.

Hosted CI gives only its pytest step a fresh private `TMUX_TMPDIR`, created by `mktemp -d` with owner-only permissions as `$RUNNER_TEMP/qs.XXXXXXXX`. This keeps socket length independent of the checkout path. The session fixture still budgets the effective anchor in filesystem bytes, with the same 107-byte limit and 12-byte margin; an overly long runner temporary path still refuses. The step retains a directory descriptor, compares device/inode identity and rejects a link before empty-only `rmdir` on exit. A failed test command keeps its nonzero status even if cleanup fails; cleanup failure after success fails the step and reports the retained path. No recursive removal or peer cleanup is allowed. Uncatchable process death may leave this invocation's directory for the disposable runner to retire. The separate fake-harness drill and the unset-variable project fallback are unchanged.

**Short panes.** A failed whole-paste comparison can carry a reason-only geometry
reading: `pane too short: at least N rows needed for the unfolded message
(H available); enlarge the pane`. Only adapters with an established text-column
declaration opt in. Printable ASCII/LF supplies a conservative lower bound: spaces
and empty lines are ignored because rendering can discard separators; unsupported
layout or undeclared columns stays unknown and keeps the generic mismatch. The
bound makes no assumption about UI chrome or a program's folding threshold. All
whole/folded comparators and clear, submit, receipt, retry and human-session rules
are unchanged. Accepted folded placeholders never acquire the diagnostic.

The existing failed-paste journal retains its observed geometry. Its owner then
atomically publishes one at-most-4096-byte `.pane-obstruction` marker beside that
journal, naming only that journal, its identity, geometry and paste time. A reading
opens that marker and, only if valid, the one journal it names: it enumerates no
journal or attempt history. Journal phase, identity, payload and geometry remain
the evidence; the marker grants no admission or receipt. Saved launch metadata and
the reading's already owned frame bind the display without a pane query. Without
such a frame, saved geometry is explicitly labelled `last failed paste`. A changed
frame removes the current-geometry label without settling uncertainty or allowing
a resend. The writer removes the marker when its journal leaves pasting/withheld,
or a later paste is confirmed in the record (delivered or accepted queued input,
not a screen-only queue hint). Invalid markers read as no diagnostic and reads
never repair them. Status retains the seat and reason on overflow. An open door
can display a previous failed delivery's geometry without changing its admission decision. Human seats acquire no such
annotation. **Native renderer behavior at short heights is unmeasured**; acceptance
here uses invented 100x16 and 100x50 frames and existing measured fold contracts,
not a live native renderer or provider. No independently established clipped-boundary
form is available, so no unnumbered height diagnosis is inferred from an unknown box.

**An unread box.** Where the reader finds no box after a paste, outside a human's session, the failed-paste journal also keeps the screen it read as `paste_screen`: the reader's own reason, the screen's last 120 rows cut to 320 characters each and 24,000 in all, and the count of rows cut. Anything shaped like a credential is masked first. The blind reason names the reading and says the screen is kept. It is evidence for a person and nothing else: nothing reads it back to decide, clear or resend, and saving it can fail without changing the outcome. Grok's `VTE_VERSION` hint row was found this way.
