# Quarterdeck design: Harness adapters

A page of [the design](../DESIGN.md).

## 5. Harness adapters

One class per agent program, on one interface, `Harness` in `harness/base.py`. A new adapter writes the members below; the rest is written once in the base. Every fact about a program lives in its adapter: no module outside `harness/` names a program, and a test holds the line, taking its names from the harness registry so that each newly registered program is covered.

A program of a frontier provider starts with the trust its maker gives a person who trusts the working folder: the folder instructions, skills, hooks and tool servers load as they would for that person. The ship adds security particular to one program only afterwards, each piece on the Admiral's word. The operator's own HOME files stay out of a seat; the declared workspace is trusted separately. The existing hands and their workspace jails are unchanged.

|---|---|
| `name`, `program` | The name the ship file's `harness` gives, and the program it runs, found on the PATH or named in the ship file |
| `opening_prompt_turn` | Whether the fresh brief starts a native model turn; the live check waits for that ended record and an idle ready door before its task |
| `queued_input(text, before, after)` | Optional adapter proof of a newly visible native queue after a fully matched paste; queue visibility never supplies the exact record receipt |
| `home_variable` | The environment variable that names the program's home, where the program has one |
| `build_home(home, seat, pool, ship_home)` | The seat home written from the ship's files: settings, trust, no self-update, nothing of the user's; and how the pool's credential reaches it, by environment or by one link |
| `launch(seat, pool, home, brief, resume, first)` | The exact command line and environment for a launch, with or without resume: the brief carried without touching the user's files, appended to the system prompt, as a configuration override, as an instructions file or as the first message, and the first message where the program takes one on its command line |
| `workspace_notice(home, cwd)` | Optional read-only information about a workspace, default `None`. Doctor adds a passing row when text exists; launch carries its snapshot as `Launch.notice`, saves it as optional `Launched.notice` and prints it in the launch proof. Unknown inventory is information and never a workspace-content refusal |
| `preflight(home=None, cwd=None)` | Read-only readiness shared by doctor and adapter build/launch; the default does nothing. It makes no native program/provider call and writes nothing. It raises `ShipError` with the offending path or unreadable-state reason. Omitted context checks global layers only and never infers the operator's home or working directory |
| `records(home)`, `first_timestamp(record)`, `session_id(record)` | The record files in a home, oldest first; when one was begun; the session a resume names |
| `reader` | One pass over a record, giving the live state (the last input, whether a turn is open, the open tool call, the last write) and the ended turns (reply, tokens by class, tool calls with their durations and failures, the turn's duration, its subagent turns). A JSON-lines format writes only its `take` and `end` on the shared `JsonLinesReader` |
| `inputs(record)` | The record's evidence of each input, with its time: accepted, queued, or consumed. It is the only evidence a delivery is confirmed by, and one matching rule in `input_receipt.py` reads it for the door, the service and `qd check` alike |
| `record_time_resolution` | Declared native record timestamp resolution in seconds; zero by default preserves exact current receipt comparisons. The canonical receipt matcher floors only its local comparison time to a positive declared resolution; Grok declares one second |
| `recorded_paste(text, record, since)` | The one form a payload pasted at `since` takes in this record, where the adapter has measured the program change it; by default the payload unchanged. The receipt matcher, and the closed-record reading, accept the payload as typed or this form, never a near match; the message itself is still typed byte for byte. Claude Code 2.1.317 records each TAB of a paste as four spaces wherever it stands, in the queued entry, its removal and its attachment alike, and escapes a literal opening wrapper tag of the text, `<pasted_content`, as `<\pasted_content` inside its own wrapper (a closing tag in the text has no measured form); queue rows carry no version, so the form applies only when every row of the record from `since` that names the program's version names 2.1.317. Another or unknown version has no form until measured |
| `paste_ignored(text, record, since)` | The characters the adapter measured its program to drop from this payload as it records a paste, where their context does not keep them; by default none. The receipt matcher, and the closed-record reading, remove exactly these from the recorded text and from each form alike before comparing, and nothing else. Claude Code 2.1.317 drops a zero-width space (U+200B) from a paste, measured in its queued entry, its removal and its attachment; its own sanitiser treats every format character (category Cf) among its hidden characters the same way, keeping one only in a context it names, such as a joiner inside an emoji. Those, and only for a payload that holds one, under the same version scope as `recorded_paste` |
| `attribution_inputs(record)` | Timestamped record evidence for order attribution, normally the ordinary inputs. A program may add structured watch-output consumption here; it never becomes a delivery receipt. Complete post envelopes still have to match the immutable store |
| `screen(text)` | What a capture of the pane shows: the input box and its text, whether the program is working, a dialog or a notice, and the settings the program displays. Working is true when its sign is seen, false only when the box is seen without it, and unknown otherwise: no box, an unknown layout, a start-up frame or a composer unread (law: record-first). Every caller that decides on it holds on unknown, and `qd watch` says it could not see; `Seat.is_working` answers working for a screen it cannot read, so no caller acts as on idle. Within a launch's start-up bound (`start_seconds`, 60 by default) a boxless frame with no dialog reads as starting, cleared by time, never an obstruction that calls a person |
| `styled_screen` | Optional SGR evidence, captured with identity in the same atomic pane read; ordinary adapters retain plain text |
| `answer_seconds` | Optional adapter-owned bound for observing clearance after a fixed question answer; `None` uses the Door's five-second `ANSWER_SECONDS` default. Measured program-specific bounds and their reasons live in the adapters |
| `box(text)` | How the program shows `text` in its box before it is sent: the text itself, or the placeholder it folds a long paste into; with `box_columns(width)` where the box is narrower than the pane by other than two columns |
| `paste_clear_rules`, `paste_clear_keys(text, screen, columns, version, cursor)` | Optional versioned `PasteClearRule` descriptors and proof of the exact keys for an owned whole unsubmitted paste at its end cursor. The descriptors own the rule identity, supported version and per-logical-line keys; absence authorizes no cleanup |
| `keys` | The keys this version uses: submit, send now while working, interrupt; or that it lacks one |
| `queues_while_working(seat)` | Whether a message typed during a turn is taken and queued, or refused until the turn ends; taken unless the adapter says otherwise |
| `controls()` | What can be changed and how: for each control, a launch form (a flag, an override, an environment variable), an in-session form (a slash command), or both, and the state that confirms the change took |
| `waking_inapplicability` | Nullable named inapplicability reason for the added waking check; normal check failures never produce a waking row |
| `human_wake_box_margin(pane_width)` | Explicit proved non-input columns for a single waking row; default `None` holds, independently of legacy `box_columns` defaults |
| `check_tool_evidence(record)` | Check-only read of the temporary seat's own pinned record: at most eight last call/result pairs and 32 KiB, with named unknowns and truncation; default unsupported. No receipt or activity authority |
| `interruptions()` | The dialogs and notices this version shows: how each is recognized on the screen, and the key that dismisses it, or that it needs a human |
| `native_provider` | The native company identifier, or null for an open harness; declared in the adapter |
| `accepts(pool)` | Why the program cannot run on a pool, or nothing when it can: a subscription only in its provider's native harness, or its own provider's key. An endpoint program takes endpoint pools instead, on `EndpointHarness`, which adds `endpoint_home` and `endpoint_ready` |
| `credential_file`, `freshness(path)`, `grant_kind`, `grant_expiry(path)`, `renewal_end(path)`, `renewal_failed(path)` | Where the program keeps its sign-in in its home, how a fresher copy of it is told, and what kind of grant it is: `self-renewing` (an access grant the program renews on use), `fixed` (a login at its end) or `unknown`. `grant_expiry` is a fixed grant's end, or a self-renewing grant's short access expiry; `renewal_end` and `renewal_failed` read a self-renewing grant's renewing grant and a visible failed renewal, only from fields the adapter knows by name |
| `usage(pool)`, with `reads_usage`, `usage_interval`, `background_usage`, `headline_windows()` and `shared_usage_key(pool)`, or `usage_from_records(sources, now)` | A subscription pool's usage windows and their resets; how often they are read; whether the service reads them on its own with no seat up, or only while a seat runs on the pool; which cached windows detailed status and watch show; and which pools share one reading. A record reader receives only current joined records and saved launch times for the paying pool. A program without a usage reading leaves its pools' usage unknown, and a key pool is measured by spend |
| `usage_in_home(pool, home)`, `private_usage_home` | A native billing client gets a declared pool's private context under `runtime/pool-usage/`. The default delegates the unchanged `usage(pool)` call and creates no home. One service path reconciles reader/seat credential refreshes before and after the native call |
| `model_scoped_usage`, `usage_scope(group, model)` | Whether subscription windows have model applicability; the adapter returns true, false or unknown for a group and model. Other adapters keep their existing pool-wide grouped semantics. Source scope uses record-first running settings; a destination uses its resolved choice's model, including a program change |
| `quota_wall(text, at)`, with `screen_walls` | A wall the program shows on its screen, with its reset, where the record may not carry it; and whether the service reads a live seat's screen for one |
| `remote_control`, `wrap_slack`, `drill_settings()` | Smaller facts: whether a seat can also be opened from the operator's phone; the columns the program keeps clear when it wraps at a word; the settings of the synthetic drill, which only the fake supplies |

Grok declares background usage even when its subscription has no seat. Its existing owned usage home launches the selected program’s `agent --no-leader stdio`, initializes ACP and reads `_x.ai/billing` within a 20-second deadline; the framework adds no HTTP client. The unattended interval is a conservative 30 minutes, not a measured provider rate limit. Declared background readers honor the same in-memory Retry-After hold as live readers, with the existing one-hour cap; stored attempt times retain interval pacing across service restarts.

For Grok joins only, `first_timestamp` is the UUIDv7 session folder's millisecond creation time, accepted only when every native row agrees with that folder identity; unreadable, non-v7 or conflicting identity yields no time, with no row-time fallback or join flooring.

Written once in the base, over these: joining a launch to its record (the first record written after it, any ambiguity reported, never guessed); `state`, `turns` and `read` over the `reader`; `version(home=None)`, whose default keeps the program's existing `--version` invocation; `owns_launch(argv)`, which knows a saved launch by its program; and `control`, `recognize`, `confirms` and `is_headline`, which look up what the adapter declared.

JSON-lines adapters may override `JsonLinesReader.identifies(entry)` for their native envelope. The default retains the `type` in `kinds` rule. Grok uses native ACP `method` and `params.update` markers without rewriting source rows; the shared snapshot, cache and walk remain unchanged. Its inputs retain native physical line numbers for diagnostics.

The pi screen reader accepts the optional parenthesized provider before the model in the footer, measured on 0.79.0 at 120, 256 and 425 columns. The program omits that prefix when only one provider is available or it does not fit; the model and optional thinking level keep their existing meanings. The measured box rules, working spinner, word wrapping and line/character paste markers retain their 0.74.2 forms. Launch also passes `--no-approve`, alongside `--no-context-files` and `--no-extensions`, so 0.79.0 ignores project-local files without asking a fresh workspace's trust question. Synthetic contracts cover the layouts and launch arguments; a fresh isolated native launch reached the idle box without a trust question. A complete installed check of 0.79.0 remains separate.

`Harness.version(home: Path | None = None)` preserves its optional context contract. `Harness.private_version_home: bool = False` is the explicit opt-in; Grok declares true. The private dispatch at doctor, Seat launch and installed check calls every adapter without that flag once without arguments and creates no home, even if its version method accepts a home parameter. Only the explicit flag receives a fresh empty temporary directory under an existing owned, real, fenced ship runtime; missing or unusable context never creates or fences a runtime merely to inspect a version. An executed call is never retried without context. Grok executes the contextual lookup with `env -i`, supplying only the caller PATH, controlled native ENV and both `HOME`/`GROK_HOME` set to that empty directory; no other caller variables are inherited. Without context, Grok executes nothing and reads only the resolved selected program basename `grok-<version>-linux-x86_64`; an unrecognized name gives unknown. Both routes reuse Seat's ordinary selected-program PATH, with no redirection to another Grok or read of operator `version.json`.

Grok grants native folder trust with `--trust` for the whole repository containing the seat's declared workspace, or the workspace itself outside a repository. This includes the framework root and repositories containing project instructions and tooling. Workspace contents never refuse launch. Native 1.0.77 writes `GROK_HOME/trusted_folders.toml` atomically, using a `folders."<absolute root>"` table with `trusted=true` and `decided_at` Unix seconds. The read-only guard accepts exactly one such grant for this seat's actual repository root or non-repository workspace. It retains and refuses other folder grants, unknown/malformed state and an unknown root. A bounded read-only Git metadata query identifies only that trust root under the private environment; it neither discovers nor refuses project sources. Inherited Git redirects refuse rather than change the trust identity. Quarterdeck never rewrites the native store or its lock files.

Independent native validation established that trust loads workspace `AGENTS.md`, `CLAUDE.md`, `CLAUDE.local.md`, nested `AGENTS.md`, `.grok/rules` and skills from `.grok/skills` and `.agents/skills`. Project hooks run and project MCP servers and project LSP processes start. Compatibility `.claude` and `.cursor` imports remain off. The card distinguishes native project sources from configured-off compatibility sources. Ship brief precedence applies to project material. Every ship template, seat configuration and generated launch configuration still rejects `paths.extra_rule_dirs`, whose native imports are independent of trust.

Native startup deletes home `managed_config.toml` at every offline and online start, regardless of `features.managed_config`. Ship-written managed hooks/MCP pins therefore enforce nothing and are not written or accepted. No requirements file is written or depended on either. Both `/etc/grok/{managed_config,requirements}.toml` and home `{managed_config,requirements}.toml` refuse and remain intact. The native advisory `/etc/claude-code/managed-settings.json` can only tighten MCP; Quarterdeck neither refuses nor edits it. Grok accepts project hooks and MCP servers as the maker does for a trusting person. It adds no project-content refusal, prompt or new jail. The launch trust choice stays in Grok's own `grok_workspace.launch_args`, without a speculative ship setting; the other adapters and existing jails are unchanged.

Grok's `workspace_notice` inventories declared hook, MCP and LSP sources from the repository root through the working directory using bounded read-only metadata/file reads. Existing `.grok/hooks/*.json` contributes source paths and event names; `.grok/config.toml` and `.mcp.json` contribute declared MCP names. LSP sources include `.grok/lsp.json`, readable standard project-plugin `.lsp.json` and inline declarations in `plugin.json`. LSP serialization is unestablished: standard readable files are reported by path as `LSP: declared, shape unknown`; configuration bytes are not read and server names are not guessed. Unreadable/unrecognized sources, unresolved manifest layout, activation/path overrides and indirect sources remain explicitly `LSP: unknown`. Disabled compatibility sources are excluded. Unreadable/unrecognized sources, unknown scope and indirect plugin/agent imports are explicitly unknown, never guessed empty or refused. Rendered paths and names are escaped onto one line; command, URL, header, environment and token values are omitted. This is an inventory of declarations, not a native activation report. A positively non-repository scope says `(no repository; grant <folder>)`; an actual repository, including a repository rooted at cwd, says `(whole repository <folder>)`. This wording carries the existing positive root-resolution fact and does not infer it from root equaling cwd.

Doctor records this information as a passing row per actual seat/pool choice, separately from readiness failures. Grok launch supplies `Launch.notice`; Seat copies it by keyword into `Launched.notice`, persists it in the launch record and appends it to the launch proof. Both optional fields are appended with default `None`, and absent notices are omitted on write. Existing positional callers and old launch records keep their defaults. Other adapters return no notice and do no inventory or extra home/native work. Revisions that predate the optional field cannot read a launch record containing `notice`; rollback has that reading limit, with no automatic record stripping or format rewrite. These notices never establish delivery, identity, activation, accounting or permissions.

Private HOME/XDG and disabled compatibility imports continue to exclude operator material. The guide's `memory.enabled`, `memory_v2.enabled` and `memory_v2.batch_dream_enabled` are explicitly false, with process-wide `GROK_MEMORY=0` and `--no-memory`. The memory guide describes capture and automatic Dream as memory background work; it exposes no separate capture/automatic-Dream enable keys. Synthetic home-output checks establish configured settings, not native behavior or isolation. The documented bundled-skill ignore prefix is `GROK_HOME/bundled/skills`; disabled skills explicitly name `resume-claude`, `resume-codex` and `resume-cursor`. Effective suppression is not claimed before validation. The daemon-only `features.subagent_bundle=false` / `GROK_SUBAGENT_BUNDLE=0` switch does not establish absence of shell-bundled agents, personas or roles.

Grok startup can fetch the public `xai-org` plugin marketplace catalog. The installed guides describe marketplace policy pins and pinned plugin auto-update control, but no supported seat setting suppressing the built-in public fetch/offering has been established; the card names this behavior instead of claiming it is disabled.

The Grok fullscreen reader in `grok_screen.py` uses freshly measured 1.0.77 rounded composer boundaries, prompt, model/effort footer and hint rows. It opts into atomic styled reads, decodes SGR inside the adapter and returns plain `Screen.text`. The exact model argument hint requires the picker, command prefix and measured faint or RGB styling; brightness alone never discards content. The normal composer retains every painted row and its padding. The adapter checks every explicit terminal blank row against an unfolded payload before using the unchanged shared matcher on the remaining visible text; no trailing row is silently removed. Unknown style/layout remains unknown. Commands and model picker dialogs are distinct from the composer. Measured responding/tool displays and working-draft hint tuples supply working screen evidence; at 80 columns the draft ends with `Ctrl+c:cancel` and omits `Ctrl+x:shortcuts`. At 256 columns the same draft also draws `Ctrl+x:shortcuts` and a chip reading `Enter Enter:send now`; the immediate send-now action stays unproved. A different tuple remains unknown. Recognizing a composer alone does not prove record completion or positive queue clearance. Native turns then measured one queued follow-up, exact consumption after first completion, guarded `C-c` cancellation during the second foreground-tool turn, and same-record resume without a carried input. Measured queued hint variants are recognized; a visible queue never supplies an exact receipt. The additional immediate send-now action remains absent/unproved.

Without an acknowledgement, a fresh Grok home opens on a first-run question about keeping the account holder's coding data for training: `Help improve Grok`, with the bracketed choices `[Opt out]` and `[Opt in]`. Measured on 1.0.77 (M1 to M3, 112 x 35), the question sits directly above the composer: a blank row, the title row with both choices, the body in exact words, a blank row, then the composer's top border; in a fresh home with no turn nothing is drawn under the footer while it shows, and the program asks for SGR mouse reports. M3 showed that the banner acknowledgement belongs to each home, not to the account: a fresh home met the question again eleven minutes after the account had opted out. The ship's orders answer it no; the account's cached opt-out can also establish a local banner acknowledgement, as described below. The reader names exactly that block `first-run training-data question (Help improve Grok) for the account holder`, an `Interruption` whose `click` is `[Opt out]`; the same title with a bracketed choice in any other form near above the composer is named as the question not as measured, with no click, and needs a human; the words quoted elsewhere in the transcript are not the question. `Door.clear_known` is the only path that answers it (law: one-door): in a seat no human owns, on an empty box, on a screen that reads not working, only where the pane's modes show SGR mouse reporting on, and only on the frame read just before the press, it sends one SGR left-button press and release on the middle cell of `[Opt out]`, found by its text exactly once on the screen, never by a place. The press is written into the launch's `launch.json` as `answered` (the question, the choice, the time, `pressed`) before it is sent, and its outcome after: `cleared` once the question's words are gone and the empty composer is drawn, or `did not clear`. A launch is never pressed twice: a screen still showing the question after its press needs a human. The service's `answers` step does this for a seat with nothing to deliver; delivery and `qd check grok` reach it through the same door. `qd watch` names each answer with its time, and `qd check` reports it as a check. In a human's session the person answers it. Opt in is never pressed, and any other question a program puts to its account holder stays named and held. The adapter drops any `[privacy]` table from templates and seat settings. A native press-left acknowledgement with no framework seed record remains preserved across same-home rebuilds; its timestamp alone is never treated as proof that the framework wrote it. Before a Grok launch it reads only `coding_data_retention_opt_out` through that framework home’s linked sign-in. Only the unambiguous native boolean `true` permits it to seed `privacy.privacy_banner_acked` with an RFC 3339 timestamp; missing, false or unreadable metadata seeds nothing. This is cached sign-in evidence, not a fresh remote preference query, and a banner acknowledgement is not itself an opt-out choice. The framework never calls `setCodingDataRetention` or changes the account. The framework records its seed in the small home file `quarterdeck-privacy-seed.json`, with its writer, format and timestamp, before writing the config key. Every launch and rebuild reevaluates a recorded seed against the flag as it reads then: when it no longer reads true, the owned config key is removed before its seed record, so the native question can return. Native acknowledgements without that record are retained. A linked, malformed or mismatching seed record is held for review rather than guessed. The launch notice records `Grok privacy banner acknowledged: the account's cached opt-out reads true (framework seed)`; the existing launch-record notice carries it and detailed watch renders it beside any separately recorded press. Native billing homes use the same conditional acknowledgement before their program starts. A seeded home starts with no question, straight to the fresh composer: measured on 1.0.77 in a human-session home, frame for frame the composer drawn after the framework's own press. The Door reads that composer as the measured empty idle composer, not working, when, and only when, both marks stand: the launch record's notice ends with the seed's evidence as its own last part, and the home still holds the framework's seed record with the config's acknowledgement equal to it, on a version measured seeded (1.0.77). The notice's words alone are not enough, since a workspace inventory can carry any name; nor is a native acknowledgement with no seed record, a seed record that is linked, malformed or not the framework's, or a seed withdrawn since. Without the seed the existing rule stands: the fresh composer is idle only in a launch whose record shows the question answered and cleared. The Door applies this to its own capture, so its reading, its delivery and the human waking line's screen check read the same composer; a human-session launch on a seeded home thus reaches idle and takes the waking line, with nothing pressed. The measurement's tmux offered no truecolor, so Grok drew every frame in the 256-colour palette; the reader decodes indexes 16 to 255 as xterm's cube and grey ramp beside truecolor, and the 16 system colours stay unknown. M4 measured a launch carrying its first message as an argument, as a seat's launch does: the turn runs at once under the question, which stays drawn above the composer; its first frame drew the working hint row under the footer beneath the question, and once the turn had ended the idle hint row. So the question screen's hint row is read as on any other screen: the working hint reads working, and nothing is pressed; the idle hint reads not working; nothing at all under the footer reads not working only as the fresh form M1 to M3 measured; any other hint row leaves the question named, with no box read, and it needs a human. The press is made only on a screen that reads not working, so the cleared screen reads as an ordinary idle composer and the door opens. A fresh home with no turn shows no hint row after the press, which the reader still reads as an unmeasured hint: the press's own confirmation does not need it, but readiness does, until that form is measured. This extends `launch.json` with an optional `answered` list, absent until a question is answered; an older framework's launch reader rejects the key, so before a rollback a Grok seat whose launch carries it is brought down by the new framework's identity-checked `qd down`.

Grok draws typed spaces exactly as its padding, so its reader returns an empty composer's box as the padding spaces, and the human waking line, which needs a box of exactly nothing, could not tell an empty composer from one holding a person's spaces. Measured on 1.0.77 on 13 November, on a throwaway human session with its own tmux server: in the empty composer the visible terminal cursor sits at the prompt's first cell, column 6 of the prompt row, at 80 x 24 and at 112 x 35, and two typed spaces move it to column 8. So the Door reads a composer whose one row is only padding as empty only where the cursor sits on that cell. The adapter names the cell (`empty_cell`; the base harness names none, and the box stays as read). The Door then reads the pane once more through tmux's bracketed control frame: identity, geometry and cursor, the styled capture, then the same reading again, all in one command queue, and the two readings must be equal. That frame must belong to the same process, show the cursor visible on the named cell, and read the same box. A cursor that cannot be read, is hidden, moves during the capture or sits anywhere else leaves the padding as text in the box, so the waking line is never typed after a person's spaces. The limit, measured: Ctrl-A or Home after typed spaces puts the cursor back at the first cell, and that screen and cursor are the empty composer's.

Further zero-turn Grok measurements establish a 70-cell ordinary text wrap at an 80-column pane, including the reserved cursor cell; 70/71/140-character drafts paint as one row, 70+1 and 70+70. Explicit trailing newlines after text add retained blank rows. Multiline folding starts at four counted lines and shows `[Pasted: N lines]`, counted by LF delimiters plus one unless there is one final LF terminator; leading and additional trailing blank lines count. Three lines plus one final LF remain ordinary; three plus two final LFs fold as four. Color and monochrome forms are measured. The native chip is the visual projection compared with a payload-derived `Box.folded` pattern, as for existing adapters. Only the exact whole record input confirms delivery; a visual count is never a receipt. A wrong count fails the comparison, and no automatic folded-paste clearing is added. Whitespace-only content whose rendering collides with empty is refused. A long single-line scrolling viewport does not show the complete draft and supplies no full-paste match. This projection changes no shared matcher or payload-identity rule; LF facts do not establish other control/line-ending layouts. Declared timestamp precision is described beside the canonical receipt rule below.

Grok accounting retains each native `tool_call` once, including a cancelled call without a terminal update as `ToolCall(seconds=None, failed=None)`. Explicit later terminal evidence refines that invocation without creating another turn or call. Native `cachedReadTokens` is subtracted from total `inputTokens`; missing classes and unmeasured nonzero cache-creation semantics remain unknown. A single native `modelUsage` key supplies the turn model. Mixed models, subagent counts, per-model-call steps and normalized `costUsdTicks` remain unknown where the record or unit contract does not establish them. Full adapter coverage and limits are inventoried in [Grok contract facts](../GROK.md).

Doctor calls the native adapter's global preflight for a non-endpoint pool even without a seat, and checks each seat's actual harness for every declared pool choice with an explicit runtime home and ship-resolved cwd. Failed seat readiness and optional passing workspace notices add rows. A default adapter's output is unchanged, and an arbitrary endpoint operator never selects a native reader.

First round: `claude`, `codex`, `antigravity`. GLM is `claude` with a different endpoint and model map, so it is configuration, not a new adapter. Added on 7 November 2026: `opencode` and `pi`, both on endpoint pools ([section 4](ship-file.md#4-the-ship-file)). One OpenAI-compatible server, a local vLLM in the first ship, serves either program; each adapter writes the provider into its program's own configuration under the pool's name, so the record of every turn names the pool that served it, and asks the endpoint what it serves when the seat home is built, so the ship file names the model and nothing more about it. A program that keeps every session of a data directory in one database, as OpenCode does, is given a data directory per launch, so that a record stays one file per launch and the join stays exact. Each adapter ships a card, `harnesses/<name>.md`, with the facts a seat needs about its own program, and a fixture set per proven version for the contract tests.

An endpoint pool may also declare `output = N`, a positive integer response-token allowance smaller than its selected context window; booleans, zero, negative values and non-endpoint declarations are refused. Omission keeps the existing default: at most 8,192 tokens, one quarter of context with a 1,024-token floor. Context, total response output and reasoning are different quantities. The selected allowance is saved in `model.json`, passed through each adapter's native model configuration, and a declared allowance is shown by doctor. Our files, their flags. An adapter passes Quarterdeck's own files and overrides on the program's command line and never edits the program's configuration, the user's instruction files or the user's repository. The two forms of a control are not equal. The launch form is free when a seat comes up. The in-session form is the one for a change while it runs, because a slash command typed into the pane leaves the change in the session log, where the human can read it, and because it costs no restart; model and effort change often and quickly in a session, and `/model` or `/effort` in the pane is the visible record. A control with only a launch form needs a restart, and `qd set` says so rather than doing it quietly. A control is confirmed by the program's resulting state, the model it reports or the setting it shows, never by the echo of the command, and is left pending when that state cannot be read. The launch form also turns off whatever the program would write into its own box, such as generated prompt suggestions: each costs a model call, nobody at this keyboard uses them, and the box must hold only what someone typed. The switch that does this is a per-version fact pinned by fixture, because the door's empty-box check depends on it.

**Permissions.** A seat runs its program open: no sandbox and no approval prompt, on every program. Trusted models in a sandbox produce workarounds and spend tokens on them, and a program that stops to ask whether a step is allowed asks a question nobody at the keyboard can judge, where a no stalls the work or breeds the workaround. A ship that wants a seat sandboxed asks for it in the ship file, seat by seat, with `sandbox = true`; and a seat on an endpoint pool is sandboxed unless the ship says `sandbox = false`, because a model served locally is trusted less than the subscription programs, and the cost of a jail there falls on the model, not the operator. A program is found on the PATH `qd` runs with, or named in the ship file; nothing pins a path or a hash of its bytes, and a usage reading runs the program the way a launch does.

**The jail.** A sandboxed seat's program runs inside one `bwrap` command (bubblewrap), built by `sandbox.py` at launch and recorded in the seat's launch file: the root read-only; a private `/tmp`, capped in size; the operator's home replaced by an empty one, with only the folders the program and `qd` resolve through bound back read-only (each link's folder, the install prefix above a `bin`, the root above a `node_modules`, every PATH entry, the framework's interpreter and files); the workspace writable; the ship folder read-only with the other seats' folders hidden and this seat's own folder writable; and the post store writable, so `qd post` works from inside. The program's home is the seat home. Inside, the program still runs with every permission granted and no approval prompt: the jail draws the edge, and the program never asks. tmux is out of reach from inside: the ship's own server's socket folder, `runtime/tmux`, is an empty private tmpfs there, and a jailed seat is told no `QD_TMUX_SOCKET`; so a jailed seat posts and reads nothing else, and a reading from inside says so. The operator's files, sign-ins and the other seats' records are absent rather than forbidden, so nothing the model does inside can read or change them; the integration test orders a jailed fake seat to write its workspace, read a file of the operator's and write another, and checks the first happened and the other two did not. A seat whose working directory is the home itself jails nothing and is refused.

A jailed OpenCode hand starts the native file finder in `runtime/seats/<name>/work`. File completion searches that folder. The jail still binds the declared workspace at its original path, so the hand can use explicitly named paths there and use `QD_WORKSPACE` as the working directory of a command. A resumed OpenCode session searches its saved directory. A hand can resume only when the saved session proves the exact working folder. If the directory differs or cannot be proved, restart refuses before closing the running program. One explicit fresh start carries the brief and open or unread messages and retains the old native record.

**Versions.** The programs update often, by their own hand or the system's, and a public framework cannot pin what a user's machine installs. An adapter therefore knows its program by version: a table of facts, each row the version it was proven on, the newest row applying to anything newer. At every launch `qd` reads the installed version, and `qd status` shows it beside the running one and says whether it is proven: `claude 2.1.317 running · 2.1.320 installed, unproven`. An unproven version runs with the newest known facts applied, best effort by design, because a new version is nearly always identical in everything the adapter touches; it is never a reason to hold the ship. `qd check <harness>` proves one, live, on a throwaway seat, in one short turn. Optional `--model <id>` selects only that throwaway seat’s model, leaving the declaration and pools intact; requested-model proof requires an exact or adapter-proved identity, uses record-first confirmation with screen fallback at startup, and requires a confirming owned-record model at completion. The proof names requested, launched and record-observed models; an unconfirmed requested model fails. A missing screen model is absent evidence and does not negate a confirming owned record; an explicit current screen model must also confirm the requested identity, and a contradiction or unresolved alias prevents success. Without the flag, the existing like-seat/native-default selection remains. The program is checked as follows: the program is found and launched, its door opens, a paste long enough to fold in any box is matched as the program shows it, submitted and confirmed by the record, the program writes a named file with a given line and posts a report that closes the order, and its record is joined and the ended turn read. When every step holds, the version is marked proven in the runtime, and that is all proven means. The record's shape, the usage reading, the controls and the dialogs are not compared there: the contract tests compare them with recorded fixtures, and a version whose facts differ gets new fixtures and a new row by hand, which in the public repository is a pull request. The adapter reads the least that changes most: the record and the command line change rarely and carry the facts; the screen changes often and is read only for the box and the dialogs. An update that changes what the adapter reads shows as a withheld line or an unknown obstruction, reported, never as a wrong action taken. A seat home turns off the program's self-update where the program has the switch, so on a ship versions change when the operator says, or when the system does, and either way the status table says so.
