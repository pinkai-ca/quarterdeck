# Muse contract facts

This adapter is under construction. The source checkpoint is not a registered
harness and cannot launch a seat. Ordinary synthetic source tests passed on an
earlier checkpoint; later source corrections remain untested. Independent
help/version measurement establishes `Muse Code 1.4.15 (1.4.15-R8339.1)` from
the versioned binary directly. Help/version made no network attempt or write,
and consulted only the XDG data root for a missing feature-config file. They
did not load credentials, so auth-root and auth/login environment behavior
remain unsettled. This proves neither startup nor provider behavior.

`muse_program.py` locates the installation on the selected program PATH and
reads its `.muse-version` marker to select `muse-bin-<release>` directly. It
never executes the launcher. The marker identifies a candidate executable;
native version proof and support remain separate.

Current help documents root model/effort/contributor, approval/judge/sandbox,
trust and question switches. `--trust-workspace` is run-only, loads project
skills/rules and does not save trust. `--no-foreign-personal-context` and
`--session-id` belong to exec, not the interactive root. Resume accepts a
session reference or `--last`, with root options on either side. Documented
switches do not yet prove their effective startup behavior.

`muse_home.py` drafts pure configuration/environment output without creating a
home or reading credentials. It seeds an explicitly declared noncontributor
model and rejects contributor choices in each declaration layer. Historical
personal-context keys are written in that output; their current-version effect
is unproved. Proposed XDG roots place settings under `home/config/muse` and
records under `home/data/muse`; native startup validation is still needed.
`MUSE_AUTH_PATH` and `MUSE_LOGIN` are omitted provisionally. This is not proof
the binary ignores them, and no credential place has been selected or read.
Auth-path observation must settle the credential root before launch integration.

The adapter must accept every ship-declared workspace and grant its native
workspace trust automatically. Project instructions and tooling are disabled
only where Muse supports that while trusted; otherwise they load, and the card
and launch notice say what is known. The ship brief takes precedence. Workspace
contents never supply a refusal, additional prompt or jail.

The record draft supports the historical flat `payload_type` envelope and
retained-frame children containing `record_json`. It reads native accepted
input separately from run starts and terminals. Accepted text is not described
as queued or consumed. Current-version materialization and active-run delivery
schemas remain unproved. Run replies, named tool invocations and present output
tokens are retained; unestablished tool duration/failure, other token classes,
model, price and child-turn counts remain unknown. Root enumeration excludes
the separate subagent store. The draft does not yet account child turns.

The allowance draft decodes a versioned native-command envelope. An absent
allowance, including `no_allowance`, remains unknown. Synthetic numeric examples
use historical bucket field names; they prove parser behavior only. No current
subscribed allowance, window period, reset convention or percentage precision
has been measured for this change. Only present duration/reset/percentage fields
may establish those facts. No custom authenticated request is permitted.

The complete implementation still needs private home and launch construction,
model/contributor handling, credential metadata and replacement integration,
paced native usage, record disposition and tool/accounting schemas, measured
screen/box/keys, controls, notices, adapter registration and its program card.
Native isolation, trust/import, catalog, permissions and credential boundary
proof belongs to an independent validation stage. Echo evidence cannot establish
paid-provider behavior. A subscribed installed check and exact-tip full suite
remain required before acceptance.

The shared source draft adds optional delivery-fault and interrupt-obstruction
hooks, preserving no-op defaults and avoiding extra reads for existing adapters.
The Door requires a bounded read-only exact current fresh join, native
creation/conversation identity, and stable current launch/pane evidence before
supplying record state. Historical reader ownership is insufficient; fresh
state before its proved join and all resumed record state remain unknown.
Muse's current native identity/schema facts are still pending. No generic
current-state accessor, store or launch rewrite is added. The Door checks faults
before input actions. A guarded interrupt-speed message to positive idle is
delivered normally without an interrupt key; unknown activity withholds it.
Working interruption still needs measured native key evidence. Independent
enforcement tests are pending. The pacing source now
adds a default-false strict interval capability and records anchored refusal
deadlines in a `usage_holds` side table, preserving the old `usage_reads` shape.
Malformed/nonfinite native retry delay means an ordinary refusal held for the
upper bound of 3600 seconds from the attempt, then eligible to read subject to
the strict floor. Corrupt stored hold evidence instead requires a human and
withholds native reads, with an operational alert in both status forms. Far-future
stored timing is corrupt. The strict floor guards live and background reads;
withheld reads never advance attempt time. Attempt/hold write failure rolls
back the transaction. Old writers remain compatible;
older services retain their memory-only backoff behavior across rollback.
Synthetic schema examples and independent enforcement coverage remain unrun.
